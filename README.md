# LLComp

Беспотерьное сжатие изображений. Исторически это продолжение [FFV1](https://ffmpeg.org/ffmpeg-codecs.html#ffv1): медианный предсказатель, обратимое цветовое преобразование, контекст из квантованных градиентов соседей. Первая версия llcomp оставила от FFV1 общую модель контекстов вместо отдельной на каждый слайс.

Эту схему пересмотрели. Побитовый CABAC и большой куб зеркальных контекстов убраны. На их месте байтовый алфавит и адаптивный range coder: меньше памяти, выше скорость и лучше степень сжатия.

## Как устроено

На пиксель, по каналам:

1. **RCT**, как в JPEG-LS. Для RGB: `U = B − G`, `V = R − G`, `Y = G + ((U + V) >> 2)`. Серый и альфа идут как есть. У Y своя модель, U и V делят одну, у альфы своя.
2. **Медианный предсказатель** по левому, верхнему и диагональному соседу.
3. **Контекст** из квантованных градиентов. Режим по умолчанию (`-x 0`) маленький. `-x 11` — 256 корзин, обученных на знаковом контексте без инверсии знака, со статическим пресетом. Яркость и цвет учатся раздельно.
4. **Буква** алфавита из 31 символа (величина остатка) и сырые младшие биты класса. Буква идёт в адаптивную CDF, сырые биты — в обходной поток.

По умолчанию кадр — один кусок, одна модель на канал. `-t N` режет кадр на N полос полной ширины, по целым строкам, каждая не тоньше 512 КБ. Если не влезает, N снижается. У полосы свои модели, потоки не делят контекст. Левый сосед при таком разрезе не теряется: режется только верхняя граница полосы.

## Чередующийся range coder

Этим кодер и отличается. В одном буфере полосы живут сразу несколько range-потоков (по каналу) и один поток сырых бит. Потоки не склеиваются в конце.

Место в буфере бронируется в том порядке, в каком кодер его попросит:

- range-кодер при старте берёт 4 байта, и ещё байт на каждую ренормализацию (`range < 2^24`);
- битовый писатель берёт 8 байт, когда начинает новое 64-битное слово.

В слот пишется уже окончательный байт. Переноса, который побежал бы назад по потоку, нет. `low` 64-битный, `range` 32-битный, четыре ещё не выданных байта лежат в `low`. Если старшие 32 бита `low` стали `0xFFFFFFFF`, `range` подрезается, чтобы не переполнить их. Это гибридный carry: байт, однажды положенный в буфер, назад не переписывается. Декодер читает тот же буфер одним указателем.

## Сборка и запуск

C++17, CMake 3.21. Сторонних библиотек нет.

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target llcompc-rc llcompd-rc
```

На входе PPM P6 и PGM P5, 8 бит.

```bash
build/llcompc-rc input.ppm output.llc
build/llcompd-rc output.llc restored.ppm

build/llcompc-rc -t 2 -x 11 input.ppm output.llc
```

`-t` по умолчанию 1: кадр целиком. `-x` от 0 до 11, по умолчанию 0.

Заголовки `-x 11` в репозитории обучены на CLIC professional train 2020: 585 цветных P6 и 585 серых P5. Серый — не зелёный канал, а BT.709 по кодам sRGB: `Y = (13933*R + 46871*G + 4732*B + 32768) >> 16`. Свой корпус:

```bash
python3 llcomp_dp_train.py /path/to/images --ky 256 --kuv 256
```

Скрипт пишет `llcomp_dp_cuts.h`, `llcomp_dp_map.h`, `llcomp_dp_preset.h`. После этого пересобрать `llcompc-rc` и `llcompd-rc`.

## Замер

Один кадр, `dan-carlson-88563`, 2048×1365, 8 386 560 байт сырых пикселей. Машина — 2 ядра (Xeon Platinum 8481C, KVM). llcomp собран `g++ -O3 -march=native`, режим `-x 0`. FFV1 — ffmpeg 7.0.2, самый быстрый вариант на этой машине: один проход, level 3, Golomb-Rice (`-coder 0`), малый контекст, 4 слайса, без CRC слайса. Range-кодер FFV1 и большой контекст здесь быстрее не были.

Время — стенка всего процесса, медиана из трёх, вместе со стартом и записью файла. МБ/с = сырые пиксели / время / 10⁶.

| | Потоки | Кодирование | Декодирование | Файл |
|---|---|---|---|---|
| FFV1, rice, context 0, 4 slices | 1 | 23.8 МБ/с | 26.0 МБ/с | 1 697 422 |
| FFV1, rice, context 0, 4 slices | 2 | 28.6 МБ/с | 26.1 МБ/с | 1 697 422 |
| llcomp, один кусок | 1 | 41.9 МБ/с | 37.8 МБ/с | 1 595 339 |
| llcomp, две полосы | 2 | 80.0 МБ/с | 69.5 МБ/с | 1 598 817 |

На двух ядрах кодирование llcomp в 2.8 раза быстрее этого FFV1, файл на 98 КБ меньше. `-t 4` на двух ядрах быстрее `-t 2` не стал: делить нечего, файл чуть вырос (1 604 177 байт). FFV1 с range-кодером при тех же 4 слайсах и двух потоках медленнее, 25.8 МБ/с, и чуть плотнее: 1 581 611 байт.

## Файл

| Смещение | Что |
|---|---|
| 0 | Сигнатура `0x87` |
| 1 | Каналы (1, 3, 4) в младшей половине, режим `-x` в старшей |
| 2 | Ширина, uint16 LE |
| 4 | Высота, uint16 LE |
| 6 | Нарезка: `0xC0 \| N` — N полос по строкам |
| 7 | N длин по uint32 LE, затем сами полосы |
